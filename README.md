# TK 手机壳工作台

三家美区店（POP 1 家、ACCU 2 家），四个内容账号。店铺登录在另一台电脑的紫鸟中，用户稍后提供 API。当前没有店铺数据采集能力，所有初始经营指标为空。

生产地址：https://blank-k.cc.cd

## 运行
npm install
npm run dev
npm run build

工作台使用 D1 保存日报、店铺登记与每日巡检。生产站点仅供所有者访问。不要将访问范围改为公开，接口依赖 Sites 的所有者访问门禁；POST 另校验同源请求。

## 数据口径
- 日期：America/Los_Angeles 的完整自然日；金额 USD。
- 三店汇总必须三店对应指标齐全；未知不填零。
- 日报唯一键：date + profile。重复上传更新整条日报，空白覆盖为未知。
- 销售额使用退款前支付销售额，退款单独填写；同日退款含历史订单退款时，当日贡献是期间口径，不是订单 cohort 利润。
- 商品成本、运费、平台费、佣金、广告、其他变动费用是期间实际金额，非费率。
- 贡献利润 = gmv - refunds - productCost - shipping - fees - commission - ads - otherCost。所有输入存在才计算；不包含固定成本，不称净利润。
- 账号 clicks / views 仅在同一后台、同一窗口定义一致时解释为商品点击率。不把账号归因销售加到店铺销售。
- 待发货、超时未揽收、未处理违规为采集时点快照，写入 source 说明时间；未采集保留 null。
- 订单下降提醒：前日支付订单至少10单且下降超过50%，仅为可调整运营启发规则。

## 每日巡检
由当前 Codex 任务的 heartbeat 在美西时间09:00唤醒，读取前一完整日。无 API 时不声称已采集，只检查已入库数据；缺数首次提示后，无状态变化保持安静。
自动化可能需要本地设备在线、应用可运行、站点登录可用。没有独立的云采集服务。
通过工作台“每日巡检 → 检查所选日期”生成记录，同日重复巡检更新同日记录。
